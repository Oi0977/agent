# 03 · 向量嵌入(embedder)

> 解决的问题:把文本变成**可计算的语义表示**(512 维向量),
> 让"意思相近"变成"距离相近",检索才能用数学做。

## 1. 什么是嵌入(bare 机制)

嵌入模型把一段文本映射成一个固定长度的向量(本项目 BGE bge-small-zh-v1.5 → 512 维):

```
"Wireshark 解密 HTTPS"   → [0.025, 0.031, 0.058, ..., -0.024]  (512 个数)
"HTTPS 流量怎么还原明文" → [0.031, 0.028, 0.049, ..., -0.019]  (和上面很接近)
"Wireshark 界面主题设置" → [-0.012, 0.044, 0.003, ..., 0.037]  (和上面较远)
```

训练目标就是"语义相近的文本 → 向量夹角小"。之后"找相关文档" =
"找夹角最小的向量"——纯数学,毫秒级。

## 2. 双塔模型(bi-encoder)与非对称约定

**双塔**:query 和 passage **各自独立**过同一个模型,各自出向量,再算余弦。
"双塔"= 两边各一座编码塔,互不相见。好处:passage 向量可**离线预计算**,
检索时只算一次 query。代价:两塔无交互,精度有上限(详见《05-重排序》的对照)。

**BGE 的非对称前缀约定**(本项目最容易踩的认知坑):

```python
_QUERY_INSTRUCTION = "为这个句子生成表示以用于检索相关文章:"

embed_texts(texts)          # passage(文档块):不加前缀  ← 建库用
embed_query(query)          # query(用户提问):自动加前缀 ← 检索用
```

为什么:BGE 是**非对称**检索模型(s2p:短问题 → 长文章),训练时 query 带这句指令。
不加前缀的 query 和 passage 不在同一个对齐过的语义空间,余弦相似度失真、检索质量下降。
这是模型卡官方要求,不是可选优化。**所以 encoder 对外暴露两个语义化函数,
把约定固化在接口里,调用方想错都难。**

## 3. L2 归一化 → 内积即余弦

```python
model.encode(texts, normalize_embeddings=True)   # 每个向量长度 = 1
```

向量长度归一后,**内积 = 余弦相似度**,值域 [-1, 1]。
这决定了《04》里 FAISS 用 `IndexFlatIP`(内积索引)就能做余弦检索。

## 4. 模型加载:本地快照直载(含全部踩坑)

这是本项目踩坑最密集的地方,完整记录:

### HuggingFace 缓存结构(裸机制)

```
S:\huggingface_cache\
└── models--BAAI--bge-small-zh-v1.5\
    ├── blobs\        ← 实际文件内容(按哈希命名)
    ├── refs\         ← 版本指针
    └── snapshots\    ← "模型本体"目录(指向 blobs 的引用)
        └── 7999e1d3...\
            ├── config.json / model.safetensors / tokenizer.json ...
```

`snapshots/<hash>/` 就是模型本体——**把模型当成"本地一个文件夹"来理解**。

### 最终方案:直接解析快照路径喂给模型

```python
def _resolve_model_path() -> str:
    base = Path(r"S:\huggingface_cache\models--BAAI--bge-small-zh-v1.5\snapshots")
    if base.exists():
        snaps = sorted(base.iterdir())
        if snaps:
            return str(snaps[0])      # 本地目录路径
    return "BAAI/bge-small-zh-v1.5"   # 无缓存时退回 repo-id(需联网)
```

`SentenceTransformer(本地目录路径)` 时库发现是路径,**不走任何 hub 逻辑**,
任何版本都不联网——对库版本行为差异彻底免疫。

### 踩坑全记录(按时间线)

| 坑 | 现象 | 根因 | 解法 |
|----|------|------|------|
| 联网检查崩溃 | 启动时 HEAD huggingface.co 超时/连接重置(10054),重试后 `client has been closed` 崩溃 | 新版 sentence-transformers 启动时检查模型更新,国内网络不通 | 见下一行 |
| 环境变量开关不彻底 | `HF_HUB_OFFLINE=1` 设了还发请求 | transformers 5.x 的 PEFT 探测路径只认 `TRANSFORMERS_OFFLINE`;两个开关管不同层 | 双开关都设;或干脆用本地路径直载(最终方案) |
| 版本大跳 | 行为和之前不一样、一堆新警告 | conda 安装 openai 时连带把 sentence-transformers 升到 5.6.1、transformers 5.14.1、huggingface_hub 1.24.0 | 装"小"包也可能动全家桶,升级后要回归验证 |
| Xet 协议 401 | 下载模型报 `cas-server.xethub.hf.co 401` | 新版 huggingface_hub 默认走 Xet 存储,hf-mirror 镜像不支持 | `HF_HUB_DISABLE_XET=1` 退回普通 HTTP |

**教训沉淀**:"库要联网"类问题最稳的解法不是拦库的网络请求(开关多、层多、随版本变),
而是**给库一个本地路径**,让它根本不需要网络。

## 5. 业界选型与取舍

### 选型一:嵌入模型

| 候选 | 特点 | 劣势(对本场景) |
|------|------|------|
| **BGE bge-small-zh-v1.5(本项目)** | 中文强、100MB、本地离线免费、512 维 | 单语种(中) |
| BGE bge-large-zh / bge-m3 | 效果更好 / 多语言 | 体积与速度 ×3~5,单文档中文场景收益小 |
| M3E / text2vec | 中文可用 | C-MTEB 榜不如 BGE 系 |
| OpenAI text-embedding-3 | 效果强、省心 | 付费 + 数据外发 + 依赖网络,与"本地离线"冲突 |

**本项目的取舍逻辑**:标准按优先级 ①本地离线免费 ②中文效果 ③资源占用
(8G 显存的笔记本)④单文档量级下精度足够。small 档全占。**升级触发条件**:
多语言文档或大规模语料(效果差距会被放大)。

### 选型二:模型加载方式

| 候选 | 思路 | 问题 |
|------|------|------|
| 环境变量开关(HF_HUB_OFFLINE 等) | 拦住库的联网行为 | 开关分多层、随版本变,踩过坑 |
| **本地快照路径直载(本项目)** | 给库一个目录,它就不需要网络 | 路径硬编码(用 `_resolve_model_path` 兜住) |
| python-dotenv / 自动下载 | 省事 | 不解决联网问题;多一个依赖 |

**取舍逻辑**:稳定性 > 简洁性。联网类问题最稳的解法不是"拦请求"(面多、层多、
版本行为漂移),而是"让库根本不需要网络"。

## 6. 接口契约

```
embed_texts(texts: list[str]) -> list[list[float]]    # passage,不加前缀,建库用
embed_query(query: str | list[str]) -> list[list[float]]  # query,自动加前缀,检索用
```

两个函数底层共享 `_encode`(干活只此一份),差异仅在前缀开关。
产出向量列表交给《04-向量检索》入 FAISS 库。
