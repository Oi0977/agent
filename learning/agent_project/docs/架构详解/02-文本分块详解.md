# 02 · 文本分块(chunker)

> 解决的问题:把几十万字的整篇文本切成**大小合适、边界自然**的块,
> 让每一块能被嵌入模型处理、被检索独立命中。

## 1. 为什么必须分块(三个硬理由)

1. **嵌入模型有输入上限**:BGE 上限 512 token,整本书塞不进去
2. **检索粒度**:块太大 → 一个块混多个主题,检索命中了但 80% 是噪音,
   还挤占 LLM 的上下文预算;块太小 → 语义不完整,检索到半句话没法用
3. **引用精度**:回答引用到"块"级别,块越小引用越准

本项目取 `chunk_size=500`(字符)、`chunk_overlap=50`,中文技术文档的经验值。

## 2. 核心机制:递归字符分割(RecursiveCharacterTextSplitter)

来自 `langchain-text-splitters`——全项目唯一引入的 langchain 组件:

```python
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=chunk_size,           # 500
    chunk_overlap=chunk_overlap,     # 50
    length_function=len,             # 中文按字符数计(比 token 数直观)
    separators=["\n\n", "\n", "。", "，", "！", "？", "；",
                ",", ".", "!", "?", ";", " "],
)
chunks = text_splitter.split_text(text)
```

**算法直觉**:按分隔符**优先级**逐级降级——
```
想切一刀时,先用 \n\n(段落边界)切
  → 某段还是 > 500 字?降级用 \n(行边界)切
    → 某行还超?用句号切
      → 句子还超?用逗号切 … 最后才空格/硬切
```
效果:**尽可能在自然语义边界切分**,避免把一句话拦腰截断。
分隔符顺序是"中文标点在前"——本项目语料以中文为主。

## 3. 重叠设计(overlap=50)

相邻块共享 50 字符:
```
块A: [..............................][尾巴50字]
块B:                             [尾巴50字]..................
```
**为什么**:关键信息恰好在切割边界上时,不重叠 = 它只属于其中一块,
另一块语义断裂。重叠保证边界信息在两个块里都完整出现。
**代价**:总块数变多、存储和检索有少量重复——可接受的权衡。

## 4. 设计决策

- **为什么用现成组件而不手写**:分块算法本身是纯文本工程,
  没有"藏起来的机制"值得手写(对比:FAISS 检索就必须手写才能理解 id 映射);
  递归分割是成熟方案,langchain 这个包零重依赖
- 早期写过 `step_1_chunking.py`(简单定长切分,学习用),被 smart 版替代,
  保留作学习记录——对比着看能直观感受"递归分割好在哪"

## 5. 业界选型与取舍

### 选型一:分块策略

| 候选 | 原理 | 效果 | 成本 |
|------|------|------|------|
| 定长切分 | 每 N 字一刀 | 差,句子拦腰断 | 零 |
| **递归字符(本项目)** | 分隔符优先级降级 | 好,边界自然 | 零依赖增量 |
| 语义分块 | 相邻句算 embedding 相似度,骤降处切 | 更准,主题聚簇 | 每个句子都要过嵌入模型,成本 ×N |
| 结构感知 | 按 Markdown 标题/HTML 标签/版面切 | 最好 | 依赖文档自带结构(PDF 没有) |

**本项目的取舍逻辑**:①语料是 PDF 纯文本流,没有可靠结构可依 → 结构感知出局;
②313 块的量级,语义分块的嵌入成本可承受,但收益要等检索效果真的卡在"主题混杂"
时才兑现 → 递归字符先跑;③递归字符是业界默认(Dify 默认也是它),对标学习价值高。
**升级触发条件**:出现"一个块里混两个主题导致检索噪音"的实际案例 → 上语义分块。

### 选型二:自己写还是用库

用 `langchain-text-splitters`(单包零重依赖):分块是纯文本工程,没有隐藏机制
值得手写(对比:FAISS 的 id 映射就必须手写才能懂);算法成熟,重复造轮子无学习收益。

### 参数取舍:chunk_size=500 / overlap=50

经验起点值,不是推到最优的:500 字让每块承载 1~2 个完整知识点,50 字重叠(10%)
防边界断裂。**真正的方法论是"可调参 + 用检索效果验证"**——将来做评测集后可对比
300/500/800 的检索命中率再定。

## 6. 接口契约

```
smart_chunk_text(text, chunk_size=500, chunk_overlap=50) → list[str]
```
